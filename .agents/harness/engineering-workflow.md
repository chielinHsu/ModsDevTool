# 共用工程流程

與技術棧無關、可跨專案重用的工作流程。專案事實見 `AI_CONTEXT.md`，專案慣例見 `.agents/harness/project-rules.md`；兩者與本檔衝突時，以專案文件與使用者本次明確要求為準。

## 0. 先確保版控

- 開始任何工作前先確認專案在 Git 版控下（`git rev-parse --is-inside-work-tree`）。
- **專案沒有版控時，第一步就是建立版控**：`git init`，建立或補齊 `.gitignore`（排除秘密、私人資料、依賴、建置產物、個人設定與量測輸出），再開始其他工作。
- 建立初始基準 commit 前先向使用者確認；commit／push 授權規則不因此放寬，stage 時明確列出路徑。
- 版控已存在但無法使用（例如 dubious ownership）時，回報原因與可選處理方式，不擅自修改全域 Git 設定。

## 1. 依任務類型選流程

| 任務類型 | 流程 |
|---|---|
| 問答與狀態 | 理解 → 查證 → 回報 |
| 問題診斷 | 取得證據 → 重現 → 追查根因 → 回報 |
| 程式修改 | 理解 → 探索 → 決策審查 → 計畫 → 實作 → 驗證 → 審查 → 交接 |
| 效能改善 | 建立基準 → 量測 → 找瓶頸 → 修改 → 再量測 |

- **理解**：確認目標、範圍、驗收條件與限制；只有影響後續工作的缺漏才提問，其餘以合理預設繼續並在回報中標明。
- **探索**：讀實際程式、設定、測試與 Git 狀態，不憑記憶或過去對話推斷現況。
- **決策審查**：依第 3 節列出受影響面向，決定是否需要 ADR 或流程圖。
- **計畫**：列出要改的檔案、步驟、驗證方式與回復方式；高風險工作先交架構角色或使用者確認。
- **實作**：只改本次範圍，保留無關內容與他人未提交修改。
- **驗證**：依第 5 節執行專案實際驗證指令並記錄結果。
- **審查**：檢視 diff，確認沒有無關變更、秘密、私人資料或虛構結果。
- **交接**：依 `ai-handoff` skill 更新交接單、狀態與紀錄。

## 2. 事實、假設與結論分開

- **Observed Fact**：有命令輸出、檔案內容、日誌、截圖或使用者陳述作為來源的事實，附來源。
- **Hypothesis**：尚未證實的推測，寫明要用什麼證據證實或排除。
- **Conclusion**：由事實推得的結論；證據不足時寫「目前最可能」並保留假設身分。
- 不把推測寫成根因；不把「沒有錯誤訊息」當成「行為正確」。

## 3. Decision／Evidence／Verification

變更影響下列任一面向時，在計畫、ADR 或回報中留下三項紀錄：

- 架構、資料契約（API、schema、檔案格式）、資源生命週期、並行與重入、安全與權限、效能、相容性與遷移、驗證方式。

| 欄位 | 內容 |
|---|---|
| Decision | 選了什麼、不選什麼 |
| Evidence | 支持決定的程式位置、量測、文件或規格 |
| Verification | 用什麼命令或檢查證明決定落實，結果如何 |

## 4. 流程圖

- 跨函式、跨模組或跨執行緒（含 Cron、佇列、Worker、背景工作）的變更，提供依**實際程式碼**推導的修改前後流程圖。
- 文件保存 Mermaid 原始碼（```` ```mermaid ```` 區塊），不只放圖片。
- 單純局部修改不強制畫圖。

## 5. 驗證

1. 驗證命令以專案實際設定為準，記入 `AI_CONTEXT.md` 的「建置與測試」；不得虛構指令或成功結果。
2. 驗證涵蓋程度使用固定詞：
   - `VERIFIED`：本次範圍的關鍵行為已用實際命令或操作確認。
   - `PARTIALLY VERIFIED`：部分行為已確認，列出未涵蓋部分。
   - `NOT VERIFIED`：未執行驗證，寫明原因。
3. 實際失敗另外明列（命令、輸出摘要、影響），不以「未驗證」掩蓋失敗。
4. 區分「靜態設定通過」與「平台實際載入／執行成功」；模擬、合成資料或本機測試不等同正式環境、實機或真實帳號驗證。

## 6. 回報

說明發現、變更、驗證及剩餘問題，篇幅依任務複雜度調整。小任務可以幾行完成；跨模組或高風險任務附 Decision／Evidence／Verification 與未驗證事項。

## 7. 嘗試與升級

- 同一問題的嘗試要記錄做法與證據；重複相同做法不算新的有效嘗試。
- 兩次有證據、有調整做法的有效嘗試仍失敗時，依 `MODEL_ROUTING.md`（Claude）或主動向使用者說明（Codex）升級處理方式。
- 無法取得進展時，整理證據、已排除假設與缺少資訊，交由使用者決定。

## 8. 安全底線

- 不提交秘密、憑證、私人資料庫、匯出檔或個人資料。
- 未經授權不 commit、push、部署、發布或執行會產生費用的操作。
- 不覆蓋來源不明的未提交修改；先確認 `git status` 與交接單。
